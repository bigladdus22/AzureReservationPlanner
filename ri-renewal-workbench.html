STAGE 1

Access the customer must grant

Reservations are tenant-level resources — they do not inherit permissions from subscriptions, so no subscription role makes them visible. One of the following is required in the customer tenant:

Reservations Reader — tenant scope RECOMMENDED

Read-only across every reservation in the tenant with a single assignment (Microsoft.Capacity/*/read). A Global Administrator elevates access, then assigns it from Home → Reservations → Role assignment. Covers both listing and the utilisation summaries.

Per-reservation Reader FALLBACK

An existing owner or billing admin adds you as Reader on each reservation order via Access control (IAM). Works in constrained tenants where tenant-scope roles are refused — the script below has a manual-order mode built for exactly this case.

Billing administrator ALTERNATIVE

EA Enterprise Administrator (read-only suffices to view) or MCA billing profile Reader/Owner/Contributor sees all reservations paid through that agreement via Cost Management + Billing → Reservations — no RBAC assignment needed.

Symptom check: the error does not have authorization … 'Microsoft.Capacity/reservationOrders/reservations/read' over scope '/providers/Microsoft.Capacity' means none of the above is in place yet. Subscription Owner/Reader will never fix it.
STAGE 2

Run the export in Cloud Shell

Paste-safe (no param block — configuration is plain variables at the top) so it works pasted straight into the Cloud Shell PowerShell prompt as well as saved as a .ps1. It pulls 30 days of daily-grain utilisation per reservation, excludes the unreliable last 24 hours, and writes the CSV this page analyses.

Azure Cloud Shell — PowerShell · Get-RIUtilisationReport 

    


    

      
Constrained tenant? If tenant listing is refused but you have per-order Reader,
      fill $ManualOrders at the top with the reservation order IDs from
      the portal URL or IAM blade — the script switches to per-order mode automatically.

      
Data window. Trailing 30-day and 7-day averages are hour-weighted
      (UsedHours ÷ ReservedHours), which stays honest when quantities changed mid-window. The last 24h is excluded
      because usage data arrives late and skews low.

      
Getting the CSV out. When it finishes:
      download RI-Utilisation-Report_*.csv in Cloud Shell, then drop the
      file into Stage 3.
